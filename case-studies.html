FLAGSHIP / PYTHON CLI / RELEASE 0.1.1

RepoLens

Problem

Engineering evidence is scattered across source, tests, security tools, CI and repository hygiene. Separate outputs make it hard to assess a repository consistently.

Product and my contribution

I designed and shipped a Python CLI that acquires local Git or public GitHub repositories, gathers static evidence and produces one deterministic assessment. Python AST checks, hygiene rules, conventional testing observations, optional Bandit 1.9.4 and static GitHub Actions checks feed console, JSON and HTML reports.

Engineering decisions

  • No target execution: no imports, dependency installs, tests, builds or target workflows. Acquisition validates public HTTPS GitHub URLs and constrains Git configuration, timeouts and filesystem traversal.
  • Typed boundaries: immutable domain models separate acquisition, analyzers, orchestration, scoring, reporting and the CLI. Analyzer failures remain explicit rather than contaminating other results.
  • Deterministic scoring: fixed rule metadata, exact decimal arithmetic and evidence-backed deductions. Unsupported and not-applicable analysis have different semantics; missing applicable analysis cannot silently produce a clean score.
  • Bounded processing: limits for traversal, source size and tool output reduce exposure to hostile input. Acquisition is not an operating-system sandbox.
  • Versioned contracts: JSON schema 1 and explicit TOML configuration schema 1; target configuration is never automatically loaded. Score and severity gates provide CI exit behavior.
  • Deliberate delivery: Ubuntu/Windows CI on Python 3.13/3.14, Ruff and strict mypy. SHA-pinned Actions and manually approved OIDC Trusted Publishing separate building from privileged publication.

Quality and shipped result

Release 0.1.1 is published on PyPI under Apache-2.0. The 7 October release record reports 1,235 passing local tests on each Python version, one Windows privilege skip, and 99.62% / 99.58% coverage. All four release-source CI jobs passed; the inspected hosted Windows/Python 3.13 job ran 1,236 tests with 99.65% coverage. These are RepoLens’s own tests and dated release evidence, not tests or coverage measured in scanned targets.

Limitations

Python-first static analysis with language-independent hygiene/CI checks. No private GitHub authentication, non-Python source analyzers, target dependency vulnerability auditing, or implemented Documentation/Maintainability analysis. Testing observations do not execute tests or measure target coverage. GitHub Actions checks are limited static signals. Scores do not certify runtime correctness or security.

PyNivo

Problem and contribution

Give beginners an offline place to edit Python, run it and interpret errors without a separate setup workflow. My work includes the application, execution/recovery controls and Windows packaging.

Approach and challenge

Multi-tab editing, atomic saves, session recovery and separate-process execution. Output is bounded and decoded incrementally; process-generation handling prevents stale output from a previous run.

Result and boundaries

71 tests in the inspected Python 3.13 hosted job at d6c9cc8 on 5 October; CI also covers Python 3.11. The published preview points to an older September revision. Learner code is not sandboxed; broader installer and device acceptance remain open.

Vendiqo

The problem

Track purchasing, sales and referenced returns without losing the inventory story.

Engineering decisions

An immutable movement ledger supports atomic local operations. Recovery validates archives before mutation, checks the WAL checkpoint, keeps a rollback copy and atomically replaces the live database. Historical customer names survive replay.

Verification

Main integration record at 6730820, reviewed 9 October 2026: 183 tests on Python 3.14.7; Ruff, strict mypy, frozen startup/migration/backup verification and Inno compilation reported passing. Earlier 5 October Windows CI covered Python 3.13 and 3.14. These are dated repository records, not new execution for this portfolio.

Release boundaries

Standard delivery remains unsigned; target-machine installation and physical-printer acceptance remain manual gates. Credit/collections, issuance balance snapshots and due-first returns are now integrated into main. No roles, authentication or live FBR transmission are claimed.

Python · Qt · SQLite · pytest · Inno Setup

Local budgeting · MVP

Spenvera

The problem

Make income, spending, savings and debts understandable without an account or application server.

Engineering decisions

Native SQLite and web storage use separate adapters. Backups validate envelope metadata, size and nested payloads before replacement. Web restore captures previous values and attempts rollback on failed writes; incomplete rollback is reported.

Verification

51 tests recorded in the 5 October audit at 8f1cd1a, including corruption guards and production migration/trigger SQL checks in Node SQLite. These do not establish Expo adapter or device acceptance. Android file-picker access was reported verified on the owner’s phone.

Release boundaries

Wider device and release acceptance remain open. Backups are unencrypted and native/web formats are incompatible. Web rollback is not a transaction; web reminders are disabled.

Expo Router · React Native · TypeScript · SQLite
